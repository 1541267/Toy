순회(Traversal) 4종 + BST insert/search/delete(successor 전략) 시각화

📖 트리 학습 노트 (클릭해서 펼치기)
🌳 이진 트리 (Binary Tree)

🌳 트리(Tree)란

  • 배열/연결리스트 같은 선형 구조와 다른 비선형 구조
  • 정렬 안 된 배열: 탐색 O(n) / 연결리스트: 탐색 O(n) / 정렬된 배열: 탐색 O(log n)이지만 삽입·삭제 O(n)
  • 탐색 빠르면 삽입·삭제 느리고, 삽입·삭제 빠르면 탐색이 느린 트레이드오프를 완화하려는 구조 → 균형 트리(BST/AVL/Red-Black)는 셋 다 O(log n)을 노림

🔤 용어

  • root: 부모가 없는 최상위 노드 / leaf: 자식이 없는 노드
  • depth: root → 해당 노드까지의 간선 수 (root의 depth = 0)
  • height: 노드 → 가장 먼 leaf까지의 간선 수 (leaf의 height = 0)
  • degree: 노드가 가진 자식의 수, 이진트리는 모든 노드의 degree가 최대 2

🧭 순회(Traversal) 4가지

  • preOrder: 노드 진입하자마자(자식 보기 전) 저장 → root가 항상 맨 먼저
  • inOrder: 왼쪽 서브트리 끝나고 돌아온 직후, 오른쪽 가기 직전 저장 → BST에서는 이 순서가 곧 정렬된 순서
  • postOrder: 왼쪽/오른쪽 다 처리하고 나서야 저장 → 자식 결과가 먼저 필요한 계산(디렉토리 용량 합산, 트리 삭제)에 사용
  • levelOrder: Queue를 이용한 BFS → 같은 depth끼리 좌→우로 방문, poll 하면서 자식을 다시 add
  • pre/in/post는 동일한 재귀 뼈대에서 저장(add)하는 위치만 다름

⏱ 순회 시간/공간 복잡도

순회 방식 시간복잡도 추가 공간복잡도
preOrder / inOrder / postOrder (재귀) O(n) O(h) - 호출 스택에 root~현재 경로만 쌓임
levelOrder (Queue 기반 BFS) O(n) O(w) - 큐에는 항상 같은 depth 노드들만 담김 (w=가장 넓은 레벨의 노드 수)

4가지 모두 노드를 정확히 한 번씩 방문하므로 시간복잡도는 O(n)으로 동일, 추가 공간복잡도(h vs w)만 다름

🔍 이진 탐색 트리 (Binary Search Tree)

🔍 BST 규칙

  • 모든 노드에 대해 왼쪽 서브트리 값 < 노드 값 < 오른쪽 서브트리 값
  • 탐색: 찾는 값이 크면 오른쪽, 작으면 왼쪽으로만 이동 → 매 단계 후보가 절반씩 줄어듦(이분탐색과 동일 원리)
  • 삽입/삭제도 탐색과 같은 방식으로 위치를 찾고 링크만 변경
  • inOrder 순회 = 오름차순 정렬 결과 (BST의 핵심 성질, 정합성 검증 수단으로도 사용)

⚠️ 편향 트리(Skewed Tree) 함정

  • [1, 2, 3, 4, ...]처럼 이미 정렬된 순서로 insert하면 매번 compare>0만 나와서 오른쪽으로만 자식이 붙음
  • 사실상 연결리스트가 되어 탐색/삽입/삭제 모두 최악의 경우 O(n)으로 저하
  • 이 문제를 구조적으로 방지하는 게 AVL Tree / Red-Black Tree (회전으로 균형 유지)

✏️ insert(e) - 반복문 + parent 추적

  • curNode를 root부터 시작해서 compareTo 결과에 따라 left/right로 내려가며, 동시에 parent도 한 칸씩 같이 따라 내려감
  • curNode가 null이 되는 시점(= 빈 자리를 찾은 시점)에 반복 종료
  • 마지막에 parent와 비교해서 그 자리(left/right)에 새 노드를 연결, 중복 값은 예외 처리

🔎 search(e)

  • insert와 동일한 탐색 로직(compareTo로 left/right 이동)
  • 값을 찾으면 그 노드를 즉시 반환, 끝까지 못 찾으면(curNode==null) null 반환

🗑 delete(e) - 재귀 + "서브트리의 새 루트를 리턴" 패턴

  • doDelete(node, e)가 이 서브트리의 (바뀌었을 수도 있는) 루트를 리턴하고, 호출부는 node.left = doDelete(...) 형태로 그 결과를 자기 자식 자리에 그대로 대입 → 이 패턴 하나로 모든 링크 갱신이 자동 처리됨
  • delete(e) 호출부에서도 root = doDelete(root, e)로 재대입 필요 (내부 변화는 지역 변수의 변화일 뿐, 명시적 대입이 있어야 실제 링크가 갱신됨)
  • 자식 없음(leaf): node=null 리턴 → 부모→이 노드로의 링크가 끊어짐 (실제 삭제)
  • 자식 하나: 있는 자식을 그대로 리턴 → 그 자식이 삭제된 노드의 자리를 대신 차지
  • 자식 둘 다 있음: successor(오른쪽 서브트리의 최솟값)를 찾아 값만 복사 후, 오른쪽 서브트리에서 진짜 successor 노드를 재귀로 삭제
  • successor는 정의상 왼쪽 자식을 가질 수 없으므로(있었다면 그게 더 작은 successor여야 함) 삭제는 항상 leaf/자식하나 케이스로 축소됨

⏱ BST 시간복잡도

insert(e) O(log n) O(n)
delete(e) O(log n) O(n)

📄 소스 코드
공통 부분 - Node 
static class Node<E> {

  private E data;
  private Node<E> left;
  private Node<E> right;

  public Node(E data) {
    this.data = data;
    this.left = null;
    this.right = null;
  }
}
이진 트리 - 순회(Traversal) 
// root -> left -> right
public ArrayList<E> preOrder() {
  ArrayList<E> result = new ArrayList<>();
  if (root != null) {preOrder(root, result);}
  return result;
}

private void preOrder(Node<E> node, ArrayList<E> result) {
  if (node == null) {return;}

  result.add(node.data);
  preOrder(node.left, result);
  preOrder(node.right, result);
}

// left -> root -> right
public ArrayList<E> inOrder() {
  ArrayList<E> result = new ArrayList<>();
  if (root != null) {inOrder(root, result);}
  return result;
}

private void inOrder(Node<E> node, ArrayList<E> result) {
  if (node == null) {return;}

  inOrder(node.left, result);
  result.add(node.data);
  inOrder(node.right, result);
}

// left -> right -> root
public ArrayList<E> postOrder() {
  ArrayList<E> result = new ArrayList<>();
  if (root != null) {postOrder(root, result);}
  return result;
}

private void postOrder(Node<E> node, ArrayList<E> result) {
  if (node == null) {return;}

  postOrder(node.left, result);
  postOrder(node.right, result);
  result.add(node.data);
}

// BFS, Queue 사용
private ArrayList<E> levelOrder() {
  ArrayList<E> result = new ArrayList<>();
  if (root == null) {return result;}

  Queue<Node<E>> queue = new ArrayDeque<>();
  queue.add(root);

  while (!queue.isEmpty()) {
    Node<E> curNode = queue.poll();
    result.add(curNode.data);

    if (curNode.left != null) {queue.add(curNode.left);}
    if (curNode.right != null) {queue.add(curNode.right);}
  }
  return result;
}
이진 탐색 트리 (BST) - insert / search / delete 
public void insert(E e) {
  if (e == null) {throw new IllegalArgumentException("삽입하려는 요소가 null");}
  Node<E> newNode = new Node<>(e);

  if (root == null) {root = newNode; return;}

  Node<E> curNode = root;
  Node<E> parent = null;

  while (curNode != null) {
    parent = curNode;
    int compare = e.compareTo(curNode.data);

    if (compare == 0) {
      throw new IllegalArgumentException("중복된 요소 삽입 시도");
    } else if (compare < 0) {
      curNode = curNode.left;
    } else {
      curNode = curNode.right;
    }
  }

  if (e.compareTo(parent.data) < 0) {
    parent.left = newNode;
  } else {
    parent.right = newNode;
  }
}

public Node<E> search(E e) {
  Node<E> curNode = root;

  while (curNode != null) {
    int compare = e.compareTo(curNode.data);

    if (compare == 0) {return curNode;}
    curNode = compare < 0 ? curNode.left : curNode.right;
  }
  return null;
}

public void delete(E e) {
  root = doDelete(root, e);
}

private Node<E> doDelete(Node<E> node, E e) {
  if (node == null) {return null;}
  int compare = e.compareTo(node.data);

  if (compare < 0) {
    node.left = doDelete(node.left, e);
  } else if (compare > 0) {
    node.right = doDelete(node.right, e);
  } else {
    if (node.left == null && node.right == null) {
      node = null;
    } else if (node.left == null || node.right == null) {
      node = node.left == null ? node.right : node.left;
    } else {
      Node<E> successor = findMin(node.right);
      node.data = successor.data;
      node.right = doDelete(node.right, successor.data);
    }
  }
  return node;
}

// 왼쪽 자식이 없을 때까지 계속 left로 이동 -> 서브트리의 최솟값
private Node<E> findMin(Node<E> node) {
  Node<E> curNode = node;
  while (curNode.left != null) {curNode = curNode.left;}
  return curNode;
}
