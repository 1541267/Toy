스택(Stack, LIFO) - 배열 기반 / 연결리스트 기반

같은 push/pop 연산을 배열 기반과 연결리스트 기반에 동시에 적용해 내부 동작 차이를 비교

📖 스택 학습 노트 (클릭해서 펼치기)

🔍 개념

  • LIFO(Last In First Out) - 마지막에 삽입된 원소가 가장 먼저 나옴
  • push(e) / pop() / peek() 모두 O(1) (배열 기반 push는 Dynamic Array처럼 Amortized O(1))
  • top - 배열 기반은 "다음 원소가 들어갈 인덱스", 연결리스트 기반은 "head 역할을 하는 참조"
  • 두 방식 모두 연산이 한쪽 끝에서만 발생 -> 반대쪽 끝(tail) 접근이 필요 없음
push/pop/peek O(1) 배열 push Amortized O(1) 공간 O(n)

🗑️ Loitering Object (배열 기반 전용 이슈)

  • 배열 기반 pop()은 top을 감소시키는 논리적 삭제만으로는 참조가 끊기지 않아 GC가 회수하지 못하는 Loitering Object 발생
  • stack[top] = null 처리를 꼭 해줘야 GC 대상이 되고 메모리 누수를 방지
  • 연결리스트 기반은 top = top.next로 재할당하는 순간, 제거된 노드를 참조하는 변수가 아예 없어져 별도 null 처리 없이 자동으로 GC 대상

📌 배열 기반 구조 특징

  • Dynamic Array 구조 사용 (ArrayList의 addLast/removeLast와 동일 구조)
  • push/pop이 항상 배열 끝쪽에서만 발생 -> 앞쪽을 밀거나 당길 필요 없음
  • growIfNeeded() - top == capacity 이면 capacity를 2배로 확장(Amortized O(1)의 근거)

📌 연결리스트 기반 구조 특징

  • top: head 역할, 새 노드는 항상 top.next에 삽입 (head 삽입)
  • push(): newNode.next = top; top = newNode;
  • pop(): top.data 저장 -> top = top.next -> data 반환 (head 제거)
  • 스택은 한쪽 끝만 사용하므로 tail 포인터 & 이중 연결이 불필요

⚖️ 배열 vs 연결리스트 선택 기준

  • 배열 기반
  • 데이터 크기가 대략 예측 가능할 때
  • 연속 메모리 -> CPU 캐시 친화적
  • 원소 자체 외 메모리 오버헤드가 적음
  • 구현이 단순
  • 연결리스트 기반
  • 크기 예측이 어려울 때
  • 추가/삭제가 빈번하고 크기 변화가 클 때
  • 재할당 없이 필요한 만큼만 동적 확장
  • 노드마다 next 참조 오버헤드 존재

📄 소스 코드
ArrayBasedStack - push() / growIfNeeded() / pop() 
Object[] stack;
private int capacity, top = 0;

public ArrayBasedStack() {
  this.capacity = 10;
  this.stack = new Object[capacity];
}

public ArrayBasedStack(int capacity) {
  if (capacity < 0) {
    throw new IllegalArgumentException("잘못된 용량 초기화, capacity: " + capacity);
  }
  this.stack = new Object[capacity];
  this.capacity = capacity;
}

public void push(E e) {
  growIfNeeded();
  stack[top++] = e;
}

private void growIfNeeded() {
  if (top == capacity) {
    capacity = capacity == 0 ? 1 : capacity * 2;
    stack = Arrays.copyOf(stack, capacity);
  }
}

// pop() 한 top 데이터를 null 처리 해줘야 GC 대상이 되어 메모리에 남지 않음
// 배회하는 객체(Loitering Object) 방지
@SuppressWarnings("unchecked")
public E pop() {
  if (top == 0) {
    throw new NoSuchElementException("Empty Stack");
  } else {
    E value = (E) stack[--top];
    stack[top] = null;
    return value;
  }
}

@SuppressWarnings("unchecked")
public E peek() {
  if (top == 0) {
    throw new NoSuchElementException("Empty Stack");
  } else {
    return (E) stack[top - 1];
  }
}

public int size() {return top;}

public boolean isEmpty() {return top == 0;}
LinkedListStack - push() / pop() / peek() 
private static class Node<E> {
  private final E data;
  private Node<E> next;

  private Node(E data) {this.data = data;}
}

private Node<E> top;
private int size;

// top: head 역할, 새 노드는 항상 top.next 위치(head)에 삽입
public void push(E data) {
  Node<E> newNode = new Node<>(data);
  newNode.next = top;
  top = newNode;
  size++;
}

// top = top.next 재할당만으로 이전 head는 참조가 끊겨
// 별도 null 처리 없이 자동으로 GC 대상이 됨
public E pop() {
  if (top == null) {throw new NoSuchElementException("Empty Stack");}

  E data = top.data;
  top = top.next;
  size--;

  return data;
}

public E peek() {
  if (top == null) {throw new NoSuchElementException("Empty Stack");}
  return top.data;
}

public int size() {return size;}

public boolean isEmpty() {return top == null;}
