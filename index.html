      • Comparison Sort와 차이
        • Comparison Sort의 실행 과정은 이진 결정 트리(decision tree)로 모델링 가능 — 내부 노드 하나 = 비교 연산 1회, 왼쪽/오른쪽 분기 = 비교 결과(<= / >)
        • 모든 가능한 정렬 결과(순열)의 가짓수는 n! 이므로, 결정 트리는 최소 n!개의 말단 노드(leaf)를 가져야 함
        • 높이 h인 이진 트리가 가질 수 있는 최대 말단 노드 수는 2^h 이므로, 2^h >= n! 을 만족해야 함
        • 양변에 log₂를 취하면 h >= log₂(n!)
        • Stirling 근사(log₂(n!) ≈ n log₂n − n log₂e)에 의해 h >= log₂(n!) = Ω(n log n)
        • h는 트리의 높이 = 최악의 경우 필요한 비교 횟수(worst-case comparisons)
        • 즉 어떤 Comparison Sort도 최악의 경우 Ω(n log n)번의 비교보다 적게 할 수 없음 (mergesort, heapsort는 이 하한을 실제로 달성 → Θ(n log n))
        • 이 하한을 벗어나려면 비교 자체를 하지 않아야 함 -> Counting/Radix/Bucket Sort처럼 키의 값 구조(범위, 자릿수)를 직접 이용해 인덱싱
